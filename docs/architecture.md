# Architecture and extension guide

## Ownership

```text
src/
  config.ts                 Serializable defaults, policy, colors; async getConfig()
  index.ts                  Framework-neutral public API
  browser.ts                Browser-only public API
  core/
    json.ts                 JSONC parse/patch, JSON paths, comment-preserving edits
    project/                VFS, tree generation, safe operations, build snapshots
    schema/                 Registry, virtual overlays, cache, contextual resolution, inspector data
    language/               Highlight tokens, conservative ISL syntax tree, structural scope rows
    wallet/                 Data-only launch parameters, callbacks and run contracts
    state.ts                Serializable store with framework-neutral subscriptions
    validation.ts           Diagnostic contracts
  adapters/
    monaco/                 Models, workers, diagnostics, completion and hover
    blockly/                Shapes, palette, ordered JSON projection and serialization
    graph/                  Rete/Lit scope cards and containment ribbons
    wallet/                 Popup callback capture, persistence and return consumption
    files.ts                Browser imports/downloads and GC VFS/archive adaptation
    build.ts                Official GC browser builder/validator boundary
    persistence.ts          Version gate and project-session persistence
    examples.ts             Normalized official GitHub examples
    edit-links.ts           GC codec adapter for source/project edit links
  app/                      Browser orchestration and React shell
  components/               Reusable editor, explorer, inspector, dialogs and documentation views
  styles/                   Shared theme and layout
public/
  extras.json.full          Authoring-only extension document map
```

`core/` imports no React, DOM, storage, editor, app-shell or Node modules. Adapters consume core functions. The controller owns browser policy and async operations. Components render the shared store and normalized models; they do not infer language or build semantics.

Source JSONC and the project VFS are canonical. Monaco, Blockly and Rete project those values. Blockly emits source changes through the same controller as the code editor. Inspector content and highlighter tokens are generated by reusable core functions, with rendering at the boundary.

See [workflow contracts](workflows.md) for import decisions, history, Monaco features, wallet routing and automatic diagnostics.

## Reuse

```sh
pnpm build:core
```

This emits the ESM core, declaration files and source maps in `lib/`. The package's default export map exposes the framework-neutral API and a separate config entry. Build before packing or consuming it. Direct TypeScript modules, including browser adapters and React views, are available through `gcscript-studio/source/...` for Vite/TypeScript consumers. `src/browser.ts` is a browser-only aggregate; import a specific adapter to avoid loading unrelated editors.

```ts
import { getConfig, parseJSONC, getCatalog, highlightSource, inspectValue } from 'gcscript-studio';

const config = await getConfig();
const document = parseJSONC(source);
const catalog = getCatalog(schemaBundle);
const tokens = highlightSource(source, schemaBundle, catalog, config);
const inspector = inspectValue(document, schemaBundle, catalog, ['run', 'message']);
```

`createCodeEditor`, `createBlockEditor` and `createGraph` expose lifecycle handles with explicit disposal. `tree(project)` produces explorer data without React. `toGCFiles` / `importGCFiles` adapt the project's serializable text/base64 representation to the official GC VFS format. `createStudioStore` supports alternate shells via subscriptions.

## Configuration

`getConfig()` returns an isolated, JSON-serializable copy. Await it once at the consuming composition root and inject the result. Function-name color overrides take precedence over fallback categories (`gcscript`, `extras`, `isl`, `json`, `user-defined`). The same policy colors Monaco decorations, block functions, graph rows and catalog entries. Schema property keys and ISL punctuation have their own tokens. User-named dictionary entries are not reserved language keywords.

## Schema extensions

The downloaded wallet bundle remains the runtime validation registry. `extendSchemas` clones it and attaches document-map entries from `public/extras.json.full`. Executable function unions gain references to extension documents; validation constraints are retained. ISL extensions use a separate document with an `anyOf` declaration group and structured `definitions.arguments` / `definitions.return` contracts. Existing wallet document identities cannot be overwritten. `x-studio-root: true` marks an extension that can author a root script; its contract is added as a root alternative. The supplied `$importAsScript` declaration uses this flag. Imports support keyed objects and ordered arrays.

For a new DSL extension, declare a unique `.json` document identity, `properties.type.const`, arguments, required fields, description, examples, return contract and additional-property policy. The catalog derives its origin from the extras registry. The same augmented registry feeds Monaco diagnostics, completion, syntax analysis, blocks and inspector content. Build-only directives must be resolved before wallet validation; adding an authoring declaration does not implement a new GC build handler.

ISL evaluation is recognized only where the resolved field schema explicitly references `lang.json`. Literal data containing `type` or function-like text is not promoted to executable syntax. Structured ISL blocks support a conservative call/literal subset; unsupported expressions stay as exact text. Arity is taken from contracts rather than parsed documentation prose.

## Cache, versions and async safety

The schema cache expires after 24 hours (matching GC CLI) and is keyed by full URL and separate from editable project state. It coalesces loads, repairs invalid entries, rejects HTTP failures, supports retry, and prevents an old request from overwriting a refreshed response. The Options decoration refreshes the schema and extras together.

Persisted sessions have one version gate. Mismatches pause autosave, preserve the saved payload and offer explicit backup/reset actions. Build, import and generation operations compare project identity/revision before committing. Wallet run records bind results to project identity and a destination path; a callback from an earlier project cannot write into a different project.

`core/project/edit-link.ts` owns edit-link payload contracts, validation and URL flags.
The browser codec adapter delegates to `gc.encode.url` and `gc.encodings.msg.decoder`.
The controller applies decoded imports through existing normal-mode prompts or an
explicit embedded replacement. `sessionConfig` prefixes embedded project/options/run/result
keys with `embed:` while leaving schema cache keys shared. Bootstrap scopes callback
capture before mounting React; embedded callbacks retain `embed=true`. URL view flags
are startup overrides, and `StudioState.embedded` owns compact presentation.

Documentation display has independent depth/node/character budgets and sanitizes untrusted markup. Display limits never prune validator schemas. The highlighter bounds input size, AST visits and decorations. Editor and graphical adapters own and dispose subscriptions, pending updates, models, observers, and workers.

## Verification scope

Unit tests exercise data contracts and failures. Integration tests consume the actual installed GC browser bundle with official full schemas, project builds, validation, archives and snippet generation. Browser tests exercise real Monaco, Blockly, Rete, cache refresh, direct popup launches and a simulated return endpoint. A separate core build supports Node consumers. Host-specific deployment permissions and a real signing/submission session remain destination-environment checks.

The live official schema was checked on 2026-10-26 and matched the isolated test fixture. The GC build-stage behavior was verified against the installed official `@gamechanger-finance/gc` 1.2.4 implementation and its public declarations.
